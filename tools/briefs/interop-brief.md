# Interoperability brief — one learner, one ledger, one set of records across every app

Binds RELAY (console RELAY). `console-brief.md` applies. The apps today keep separate progress stores (`bayworld-career-v1`, `underwater-career-v1`, `fairway-park-v1`, the regatta paying into Bay World's ledger, `vr-training-identity-v1`, the training records in `WebXR/shared/records.js`, episodes in `episodes.js`, xAPI in `lrs.js`). A learner who finishes a station from a Bay World job board should see it everywhere: on the job board, in the Deep, on the home page's programme rail, in the instructor console and in the export.

## Deliverables
1. `WebXR/shared/passport.js` (prefix `pp…`, `PP_…`): the learner passport, one read/write API over the existing stores rather than a new silo. `ppLearner()` (from `identity.js`), `ppRecordStation(result)` writing through `records.js` (and `episodes.js` when a session is active) so there is one record per attempt; `ppCompleted(stationId)`, `ppProgramme(programmeId)` → `{ passed, total, stars, competencyStatus }` using `competency.js`; `ppLedger()` summing reputation and credits across Bay World, the Deep, the Regatta and Fairway (read their keys; migrate by reading, never deleting); `ppAward(source, { reputation, credits, reason })` so every world pays into one ledger with the source kept; an event hook `ppOn(event, fn)` for `station-passed`, `programme-milestone`, `award`. All storage access in try/catch.
2. The round trip: every job board already opens `smartcity-x.html?sim=…&from=<app>`. Add `&return=<app page>#site=<id>` and, on a finished run, the SmartCiti.X runner (read `WebXR/smartcity/js/` app code and `WebXR/shared/game.js` for the finish hook) calls `ppRecordStation` and shows a "Back to <world>" button that returns to the site; the world then marks that board done, pays the award once (idempotent per attempt id) and advances any quest step that names that station. Do this for Bay World, the Deep, the Regatta events' briefing stations and Fairway's grounds programme; the Trade Skills rooms and the Holodeck record through the passport too.
3. One programme progress widget `ppProgressChip(el, programmeId)` used on the home page track rails, each world's job board and the instructor console's learner view, reading only the passport.
4. Records out: `ppExport()` returns CSV and xAPI statements for every attempt with the app it came from (`context.platform` / an extension) so the instructor console and the Unity `TrainingRecord.cs` shape agree; update `exports/unity/...` only through `tools/export_unity.mjs` if the record shape changes.
5. `tools/check_interop.mjs` in `check_all`: headless (stub storage) — record a pass from a Bay World board, the passport shows it, the ledger pays once for a replayed return, the quest step advances, the programme chip counts it, the export carries the source app; every app page's bundle includes `passport.js`; no app writes progress to a new key without going through the passport (grep for `localStorage.setItem` in the four worlds outside the allowed modules).
6. `docs/interop.md`: the flow in one diagram-free page, the keys, the events.

Gate with `python3 tools/bundle_webxr.py` and `node tools/check_all.mjs` (exact "All N checkers pass" line). Hand back within 45 minutes: ≤200 words, commit hashes, the check_all line.
