# Virtuals brief — project "SmartCiti.X", agent token "$Citi": the Holodeck's robotics training on the Virtuals agent platform

Binds VIRTUALS (console VIRTUALS). `console-brief.md` applies, plus these hard rules:
- **Nothing on-chain, nothing signed, nothing sent.** No wallet is created or used, no transaction, no tokenization, no job, no API call to any Virtuals or ACP service, no key or secret in the repository. Everything is configuration, code that stays unconfigured, dry runs against local stubs, and a runbook for the owner to execute.
- **Sources.** `os.virtuals.io`, `docs.virtuals.io` and the whitepaper are unreachable from this build environment. The verifiable source is the owner's public repository `AGIFutureFoundation/acp-cli`, cloned read-only at `/home/user/agifuturefoundation/acp-cli` (README.md, SKILL.md, docs/tokenization.md, docs/headless-deployment.md, migration.md, src/commands/*, src/lib/*). State only what those files say; anything about the wider Virtuals OS is marked "to verify against the official docs". No token price, supply, fee, valuation or return is stated or implied; `$Citi` is described as the agent token name the owner chose, nothing more.
- **Hermes agent.** "Hermes Agent" is taken to mean an agent runtime of that name that loads skills (verify which one the owner means; if acp-cli's SKILL.md targets a skill-loading agent runtime, follow its conventions). Prepare the agent's profile so such a runtime can load it; do not install or run any external runtime.

## Build (in this repository)
1. `docs/virtuals/strategy.md` — the integration strategy: what SmartCiti.X offers as an ACP provider agent (station evaluation of a robot or agent policy against the simulation engine; curated robot-skill datasets from the LeRobot/RLDS exports with their consent and licence fields; curriculum and skill-registry queries; a K-12 and union-trade lesson service), what it could consume as a buyer (compute, data labelling, translation review), how each maps onto acp-cli's concepts (agents, offerings, jobs, resources, subscriptions, policy, chains, wallet gate) with the exact command names from acp-cli's README, the $Citi agent token as described in acp-cli's `docs/tokenization.md`, governance and consent (no personal data, no training records, nothing without the learner's opt-in ever leaves the device), phased milestones with acceptance tests, and a risk register (regulatory review of any token before launch; verification of every protocol detail against the official docs).
2. `agents/smartcitix/` — the agent package: `agent.json` (name "SmartCiti.X", token symbol "$Citi" as a label only, description, capabilities bound to `WebXR/shared/skill-registry.js` and the passport; extend or supersede `agents/foreman/agent.json` consistently), `offerings/*.json` in the shape acp-cli's offering commands take (read `src/commands/offering.ts` and the README; every price field left `null` with a note "set by the owner"), `SKILL.md` for a skill-loading agent runtime describing how to use the SmartCiti.X tools, `hermes/` with the agent profile and tool manifest for the Hermes runtime (conventions to verify), and `runbook.md` — the owner's step-by-step to install acp-cli, configure, create the agent, publish the offerings and, only after legal review, tokenize per acp-cli's docs, with each command copied from acp-cli's README and no values filled in.
3. `tools/smartcitix_provider.mjs` — a local provider stub that implements the offerings against the platform (evaluate a policy on a station through `robot.js`; export a dataset slice through `tools/export_dataset.mjs`; answer a curriculum query from the skill registry), taking a job payload shaped like acp-cli's job model and returning a deliverable; runs only locally, no network.
4. `tools/check_virtuals.mjs` in `check_all`: the agent package validates, every offering maps to a working stub function and a real registry entry, the stub's three dry runs produce deliverables, no key, secret, private key, seed phrase or wallet address anywhere in `agents/` or `docs/virtuals/`, no price or supply figure, every acp-cli command named in the docs exists in acp-cli's README.
5. Homepage and Guide: a short "SmartCiti.X on the agent network" section on the homepage (via `tools/gen_home.mjs`, one small block, clearly marked "in preparation") and the Guide's knowledge base picks up `docs/virtuals/strategy.md`.
