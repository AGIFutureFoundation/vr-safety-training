# Robot data and agent brief — training data for robots, and a roadmap to a platform agent

Binds SYNAPSE (console SYNAPSE). `console-brief.md` applies. Read `WebXR/shared/episodes.js`, `robot.js`, `robot-embodiment.js`, `share-engagement.js`, `agent-protocols.js`, `wallet.js`, `tools/export_dataset.mjs`, `tools/eval_dataset.mjs`, `tools/robot_train.mjs`, the passport (`passport.js`), and `docs/` pages on episodes, sharing and robots.

## Robot and agent training data
1. `tools/export_dataset.mjs` gains two output formats beside what it has: a **LeRobot-style** episode layout (per-episode observation/action/reward/done arrays with a `meta/info.json`, `meta/episodes.jsonl`, `meta/tasks.jsonl`, values as JSON Lines; no parquet dependency) and an **RLDS-style** step list (episode → steps with `observation`, `action`, `reward`, `is_first`, `is_last`, `is_terminal`, `language_instruction` from the step prompt). Each carries the station id, programme, union, hazard and interruption labels, the passport's source app, and a licence and consent field; anonymised crew tags only.
2. A **task and skill registry** `WebXR/shared/skill-registry.js` generated by `tools/gen_skill_registry.mjs`: every step kind as a robot primitive with its parameters (select → reach-and-press, turn → rotate-to-angle, drag → pick-and-place, gauge → hold-in-band, track → track-a-signal, drive → path-follow), and every station as a task graph of those primitives with preconditions (PPE, lockout) and failure labels (the hazards), so a robot policy or an agent planner can consume the catalog directly.
3. `tools/robot_train.mjs` trains its baseline on the new format and reports success rate per primitive; `tools/eval_dataset.mjs` checks the new formats.
4. Consent stays as it is: nothing leaves the device without the learner's opt-in; exports are local files.

## The agent roadmap
`docs/agent-roadmap.md`: a staged plan to run a platform agent (working name "Foreman") that answers learners, recommends the next station, supervises a robot running a station in simulation, and can be registered on agent protocols. Cover: (1) the agent's capabilities as functions over the skill registry, the passport and the Guide's knowledge base; (2) a simulation harness where the agent drives `robot.js` through a station and is scored by the same engine; (3) Virtuals Protocol — its G.A.M.E agent framework (agents defined by a goal, a description, workers and functions; SDKs in Python and TypeScript) and its Agent Commerce Protocol for agent-to-agent jobs, and how Foreman's functions map onto them, **written from the repo's existing adapter in `agent-protocols.js` and general public knowledge, with a clear note that the virtuals.io sites could not be reached from this build environment and every protocol detail must be verified against the current official docs before any integration**; (4) SingularityNET and the other adapters already in `agent-protocols.js` the same way; (5) wallets, consent, data licensing and what never goes on-chain (no personal data, no training records); (6) milestones with acceptance tests. Also `agents/foreman/agent.json`: a draft G.A.M.E-style agent definition (goal, description, workers, functions with JSON-schema parameters bound to the skill registry and passport), no keys, no network code; and `tools/check_agent.mjs` in `check_all` validating the definition's functions resolve to real registry primitives and stations, the exports' schemas, and that no key or secret appears.

## Process
Start with `git fetch origin claude/vr-ar-safety-training-wkwmve && git merge --ff-only FETCH_HEAD`. Keep `docs/consoles/SYNAPSE.md`. The bundler concatenates every module into one scope and erases import aliases: prefix new top-level names (`sk…`). Commit in steps; each commit message ends with the two trailer lines in your task. Gate with `node tools/check_all.mjs` (exact "All N checkers pass" line). Hand back within 40 minutes: ≤200 words, commit hashes, the check_all line.
