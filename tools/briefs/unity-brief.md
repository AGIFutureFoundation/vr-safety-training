# Unity brief — the content bridge: every station, programme and model exported for a Unity runtime

Binds UNITY1 (console BRIDGE). `console-brief.md` applies. The platform's content stays authored in the WebXR modules; this bridge exports it so a Unity project can run the same procedures with the same scoring.

## Deliverables
1. `tools/export_unity.mjs` → `exports/unity/SmartCitiX/` (committed, regenerated by the tool, deterministic — sort keys, no timestamps):
   - `Content/stations/<id>.json` — one per procedure in `WebXR/smartcity/catalog.json`: id, title, category, programme ids, the ordered steps with kind, target, prompt, `why`, the hazards, the interruptions, the citations, `supportLine`, the scene's equipment builder names and the hit ids (read the sim modules headlessly the way `tools/lib/headless.mjs` and `tools/eval_content.mjs` do; do not hand-author).
   - `Content/programmes/<id>.json` — the curricula with ladders, competencies and Bay World / Deep anchors.
   - `Content/worlds/bayworld.json` and `fairway.json` (and `underwater.json` when `WebXR/shared/underwater-data.js` exists) — the pure data modules serialised.
   - `Runtime/` — a UPM package (`package.json` name `org.agifuturefoundation.smartcitix`, `Runtime/SmartCitiX.asmdef`, `StationCatalog.cs` (loads the JSON), `StationRunner.cs` (a MonoBehaviour state machine over the step kinds select / sequence / find / gauge / hold / track / turn / drag / drive with the same pass rules the WebXR engine in `WebXR/shared/game.js` applies), `TrainingRecord.cs` (the record shape `WebXR/shared/records.js` writes, so records round-trip), `README.md` (how to import, licence notes: only CC0 / CC-BY / marketplace-licensed models are ever exported, never the RPM avatar or the track GLB).
   - `Models/*.glb` — the equipment and fleet builders exported through three's `GLTFExporter` in node with the needed polyfills (Blob, FileReader, document stubs); if a builder cannot export, list it in `Models/MANIFEST.json` with the reason. Aim for every entry in `EQUIPMENT_BUDGET` and `FLEET_BUDGET`; keep each file small (merged geometry, no textures beyond the vertex colours the builders use).
2. `tools/check_unity_export.mjs`, in `check_all`: the export is up to date with the catalog (re-run and diff → clean), every procedure and programme has a file, the JSON parses, the C# files have balanced braces and namespaces, the package manifest is valid, `Models/MANIFEST.json` names every budget entry with a file or a reason, no model name or token in the export.
3. `docs/unity.md` — what the bridge exports, how to run it, what is not covered.
