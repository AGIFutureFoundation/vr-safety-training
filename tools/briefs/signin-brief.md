# Sign-in brief — Google, MetaMask and e-mail sign-in, a private experience per person, and a free demo with no sign-in

Binds GATE (console GATE). `console-brief.md`, `docs/sign-in.md` and the hard rule in `WebXR/shared/auth.js` apply: nothing is ever sent to an endpoint that was not configured; the static pages verify nobody and say so; no client id, key or secret is ever committed.

## What exists
`WebXR/shared/auth.js` already offers Google Identity Services (needs `googleClientId`), Microsoft, an e-mail magic link (needs `emailEndpoint`; falls back to a device passkey), and Sign-In with Ethereum through `window.ethereum` (MetaMask and other wallets). `identity.js` holds the launch context; `passport.js` (`vr-passport-v1`) and `records.js` hold progress.

## Build
1. **One sign-in entry everywhere.** A compact account chip in every page's header (home via `tools/gen_home.mjs`, every bundle, the track pages) beside the Home and help chips (`WebXR/shared/controls.js`), opening one dialog with, in this order: **Continue with Google** (Google's own button, shown only when `googleClientId` is set; otherwise shown disabled with "Google sign-in is available when this deployment is configured"), **Connect MetaMask** (SIWE through `window.ethereum`; when no wallet is present, a plain line and a link to install one; name MetaMask as text only, no logo file), **E-mail me a link** (the configured endpoint, else the device passkey), and **Try the free demo — no sign-in**.
2. **Free demo mode.** One tap enters every world and station with nothing stored beyond this tab: progress lives in `sessionStorage` under a demo namespace, a "Demo" badge sits on the account chip, and the results screens say "Demo run — sign in to keep it". On sign-in, offer to carry the demo runs into the account (explicit button, default off).
3. **A private experience per person.** Namespace the passport, records, episodes, careers and quest stores by the signed-in identity (`learner_id` hashed with the existing `hashCrewTag` style so no raw e-mail or address is used as a key): signing in shows only that person's progress; signing out hides it; another person on the same device sees their own. Migrate existing un-namespaced data once into a "This device" profile, never delete it. The share and dataset exports keep their consent gates and never include the identity's raw value.
4. **Deploy notes.** `docs/sign-in.md` gains a short "Turning on Google, MetaMask and e-mail" section: where each value goes in `WebXR/auth-config.json`, that the Google client id must list the deployed origin, that MetaMask needs no configuration, that the e-mail endpoint must mail the return link, and that token verification belongs on the deployment's server.
5. `tools/check_auth.mjs` (new, in `check_all`; or extend `check_home.mjs` if the auth checks live there): the chip and dialog on every page; with an empty config no provider touches the network; Google shows disabled without a client id; MetaMask path builds a valid EIP-4361 message against a stubbed `window.ethereum` and signs in; demo mode writes nothing to localStorage; two identities on one device see separate progress; the migration keeps existing data; no client id, key or secret in the repo.

## Process
Start with `git fetch origin claude/vr-ar-safety-training-wkwmve && git merge --ff-only FETCH_HEAD`. Keep `docs/consoles/GATE.md`. The bundler concatenates every module into one scope and erases import aliases: prefix new top-level names (`gt…`). The machine is heavily loaded: run individual checkers while you work and `node tools/check_all.mjs` once at the end. Commit in steps; each commit message ends with the two trailer lines in your task. Gate with `python3 tools/bundle_webxr.py` and `node tools/check_all.mjs` (exact "All N checkers pass" line). Hand back within 30 minutes: ≤200 words, commit hashes, the check_all line.
