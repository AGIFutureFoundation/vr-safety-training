# Languages

The platform's interface ships in 21 languages: English, Spanish, French, Arabic, Chinese (Simplified), Russian, Portuguese, Hindi, Bengali, Urdu, Indonesian, Swahili, Hausa, Amharic, Yoruba, Turkish, Vietnamese, Tagalog, Korean, Japanese and German. Arabic and Urdu are right-to-left.

## How it works

- `WebXR/shared/i18n.js` is the layer: `trT(key, vars)`, `trSet(lang)`, `trDir()`, `trApply()` and the picker. `controls.js` mounts the picker as a chip after the account chip in the page header, so every page that carries the shared chrome has it.
- The language comes from `?lang=<code>` on the launch URL, then the choice remembered in this browser, then English. `<html lang dir>` follow the choice.
- Static markup opts in with `data-tr`, `data-tr-aria`, `data-tr-ph` and `data-tr-title`. Code calls `trT()`. A key a language lacks falls back to English, and a key English lacks falls back to the text the page shipped with. A raw key never renders.
- Station step text stays in English. Outside English the runner shows "Step text in English — translation in progress" under the step. The Guide answers in English, but its buttons and messages follow the chosen language.

## The tables

`tools/i18n/en.json` holds every key. Each other language has its own `tools/i18n/<code>.json` with the same keys. A value of `"@en"` is the explicit English fallback marker. Run `node tools/gen_i18n.mjs` to write `WebXR/shared/i18n-strings.js`, then `python3 tools/bundle_webxr.py`. `node tools/check_i18n.mjs` checks the tables, the placeholders, RTL, the picker and a headless language switch. It prints each language's coverage (keys with their own text out of en.json's) and fails if any of the 21 drops below 100%. It also loads the homepage at 360x640 in Arabic, Urdu, Chinese, Hindi and Amharic and fails if the page scrolls sideways or the programme titles are not in the language.

Coverage today: all 21 languages have every key (321 of 321), programme titles and taglines included. A new English key therefore needs a value in every table, or the checker fails. Use `"@en"` only while the translation is on its way, and lower the checker's `MIN_COVERAGE` in the same change, saying why.

Sourced quotations: no key is a quotation today. If a key ever carries text quoted from a source (a partner's own words), keep the English in every table and say so in the key's commit and in the console log, rather than translating someone else's words.

Proper names stay in English inside translated text: product and world names (SmartCiti.X, Holodeck, Bay World, Bay Regatta, Fairway Park), union and body names and acronyms (IBEW, IUOE Local 3, IUEC, UFCW, Teamsters, AFA-CWA, ALPA, IAM, TWU, UAW, WHO), partner names (wojrc.org, Unspoken Smiles), place names (Hunters Point) and standard codes.

## Adding a language

1. Add `[code, native name, English name]` to `I18N_LANGS` in `tools/gen_i18n.mjs`, and add the code to `I18N_RTL` if the language is right-to-left.
2. Copy `tools/i18n/en.json` to `tools/i18n/<code>.json`. Set `_language` and set `_review` to `"machine-assisted, needs native-speaker review"`. Translate the values, keep every `{placeholder}` exactly, and leave `"@en"` for any key you have not done.
3. Run `node tools/gen_i18n.mjs`, `python3 tools/bundle_webxr.py` and `node tools/check_i18n.mjs`.

## Review

Every non-English table is machine-assisted and needs review by a native speaker. The picker's footnote says so. A reviewer edits the JSON file and, once a whole file has been reviewed, changes its `_review` to name the review. The checker currently expects the machine-assisted marker, so update `I18N_REVIEW` handling in `tools/gen_i18n.mjs` when the first reviewed file lands.
