# AGENTGYM (`ag`, port 9036): training and evaluating software agents in the Holodeck

Loop 4, SmartCiti.X Holodeck · Powered by AGI Corp. Base 949c0919.

The stations people learn on become tasks for software agents, scored by the station's own engine. Every
mechanism is named for what it is: a random baseline, a scripted expert, a word-overlap retrieval heuristic.
No language model is called anywhere in this work, and the external-agent hook ships switched off.

## What is here

- `WebXR/shared/ag-gym.js`: the agent task API over the station engine (shared/game.js `Session`), following
  ROBOTICS' `rb-env.js` contract. `agEnv({ room, api, SessionClass }, { seed })` gives `reset(seed?)` and
  `step(action)`, which returns `{ observation, reward, done, info }`, plus `summary()`.
  - **Observation:** the step's own text (`title`, `cue`, `why`), the `visible` objects (`{ id, name }`), the
    `hazardsKnown` (found by inspecting or by touching one), the live `control` state (gauge, hold, track,
    turn) and an interruption's alert text. It never carries a target id; the checker proves this.
  - **Discrete actions (`AG_ACTIONS`):** `select(id)`, `inspect(id)`, `confirm(id)`, `hint()`, `press(id)`,
    `release()`, `wait()` (plus `drive` passed through for drive steps). `confirm` operates the current
    control the way a learner's gesture does: it commits a gauge at the needle, turns a valve a quarter-turn,
    places a dragged part or presses a hold. Touching anything that is not the target is a touch, scored as
    one.
  - **Reward:** the station's own score delta / 100. The only gym-side term is `AG_HINT_COST` (0.02 per
    hint). `summary().stationScore` is the Session's score, untouched by the hint cost.
  - **Baselines (`AG_BASELINES`):**
    - `random`: uniform over the discrete actions and the visible ids.
    - `expert`: a scripted expert that reads the station's step list. It is privileged (it sees target ids),
      so it is an upper bound, not a learner.
    - `retrieval`: ranks visible objects by IDF-weighted word overlap with the step's title and cue (weight 2)
      and its sourced why (weight 1). It inspects before it touches, follows the order of mention in strict
      sequences, discounts objects already used, and asks for a hint only when nothing overlaps.
    - `retrieval-ask`: the same heuristic, but it also asks for a hint whenever the runner-up is within
      `AG_ASK_MARGIN` (1.5) of the best match.
  - **Adapter hook:** `agAdapterPolicy(env, { enabled, decide })` returns `null` unless a deployment passes
    `enabled: true` and its own synchronous `decide(observation)`. `AG_ADAPTER.enabled === false`. Only actions
    from `AG_ACTIONS` pass through. There is no network path in the module.
  - **Agent → human:** `agWalkthrough(run, room, names)` turns a run into frames a learner steps through. Each
    frame carries the step title, what the agent did in words, the outcome and the step's why.
- `WebXR/shared/ag-feedback.js`: human feedback → agent. A learner rates a demonstrated run thumbs up or down,
  with one reason from a fixed list (`AG_RATING_REASONS`; no free text). Each rating is one DATAWORKS episode
  (`dxMakeEpisode`: source `human`, kind `gym`, scenario `agent-rating:<station>`, consent receipt attached),
  stored through `dxStore`. `agPreferencePairs(episodes)` pairs every up with every down on the same station:
  `{ station, chosen, rejected, reasons }`. Nothing is trained from the pairs yet; they are recorded and paired.
- `WebXR/shared/ag-walkthroughs.js`: generated by `node tools/ag_eval.mjs --walkthroughs`. It holds 8 recorded
  runs (expert and retrieval on robot-cell, trench-box, valve-vault and boiler-room, seed 1).
- `WebXR/agentgym/index.html`: the walkthrough page. Pick a run, step through it (buttons or arrow keys), and
  rate it through DATAWORKS' consent panel (`dxMountConsent`). The bundler copies it to `dist/agentgym/`, and
  `ag-feedback.js` and `ag-walkthroughs.js` are in the shared copy list.
- `tools/ag_eval.mjs`: the eval harness. It reports success rate and steps over N stations × seeds for each
  baseline and writes `docs/perf/agent-baselines.json` (deterministic, with no wall-clock fields).
  - `--legacy` adds the pre-existing `shared/robot.js` RobotAgent for comparison.
  - `--limit`, `--stations`, `--baselines` and `--margin` select subsets for quick cycles.
- `tools/check_agentgym.mjs`: the checker (33 checks; see Checkers).

## Privacy (DATAWORKS' rules, unchanged)

- Ratings are stored only when `dxCollecting()` is true. That means opted in, an adult, signed in, not a demo
  and not K-12; an unknown signal refuses.
- They stay on the device (IndexedDB, localStorage or memory). There is no upload path.
- `dxRevoke()` deletes them with every other episode.
- Agent runs themselves are synthetic and never carry a consent receipt.
- The checker proves each of these in Node with the network primitives trapped.

## Baselines

The pass rule is the engine's own (`shared/robot.js` runEpisode): finished, 2 or more stars and no hazard hits.
Stars need at most one correction within 1.5× par. Each run covers every station in tools/lib/headless.mjs
`loadSmartCity()`: **721 stations × 3 seeds = 2,163 episodes per baseline**. Step time is 0.05 s per decision
and the cap is 900 decisions.

| Baseline | Before (pre-existing) | After: success | 95% CI (Wilson) | Mean decisions | Hazards / ep | Errors / ep | Hints / ep |
|---|---|---|---|---|---|---|---|
| Stations usable as agent tasks with text observations | 0 | 721 | | | | | |
| Legacy RobotAgent skill 1 (direct Session access, not the task API) | 100% (124 decisions) | n/a | | | | | |
| Legacy RobotAgent skill 0 | 0% | n/a | | | | | |
| random | n/a | 0.0% | 0.0–0.2% | 899.6 | 70.95 | 417.7 | 0 |
| expert (scripted, privileged) | n/a | 100.0% | 99.8–100.0% | 299.1 | 0 | 0 | 0 |
| retrieval | n/a | 0.6% | 0.4–1.0% | 354.8 | 0.79 | 21.7 | 1.21 |
| retrieval-ask | n/a | 11.5% | 10.2–12.9% | 327.7 | 0.36 | 4.75 | 9.92 |

Reading the table honestly:
- The scripted expert passing every episode shows that the task API exposes everything a station needs: text,
  objects, controls and interruptions.
- The retrieval heuristic finishes almost every station (99.7%), but it makes too many wrong touches for two
  stars (21.7 corrections per episode).
- Asking when unsure (retrieval-ask) lifts success to 11.5% and cuts corrections to 4.75 per episode, at
  9.9 hints per episode.
- Its success is bought with hints: on a 46-station subset, raising the ask margin from 0 to 1.0 took success
  from 0% to 34.8% at 13.4 hints per episode, close to one hint per station step.
- That gap between expert and retrieval is what a learned agent would have to close.

## Cycles

1. **Reason:** a task API over the station engine is only real if a scripted expert passes through it and the
   observation hides the answer. **Act:** ag-gym.js (observation, discrete actions, reward = station score
   delta) and ag_eval.mjs. **Observe:** on 3 stations × 2 seeds, expert 6/6 and random 0/6. Retrieval was 0/6,
   all truncated at 900 decisions: it kept re-touching an object the station had refused on drag and gauge
   steps.
2. **Reason:** a refused touch should rule that object out on every step kind. A gauge commit happens only near
   the band's centre, and the engine reads the needle before it ticks, so a refused commit means the wrong
   object. **Act:** apply the refusal rule on every step kind. **Observe:** robot-cell retrieval went from
   truncated (900) to finished in 91 decisions. On the full run (721 × 3), retrieval finished 99.7% but passed
   0.7% (23.7 errors/ep). Expert passed 100% (2163/2163), random 0%. The legacy RobotAgent scored 100% at
   skill 1 and 0% at skill 0.
3. **Reason:** ask instead of guessing when unsure (hint when the runner-up is within a margin). **Act:**
   `margin` option. **Observe:** on 46 stations × 2 seeds, success by margin was:
   - 0: 0.0% (1.43 hints/ep)
   - 0.3: 2.2% (9.26)
   - 0.6: 17.4% (11.17)
   - 1.0: 34.8% (13.35)

   Success tracks hints, nearly one per step at the top.
4. **Reason:** fewer wrong touches without hints: IDF-weight shared words (valve, panel) and discount objects
   already used. **Act:** both, in agRetrievalPolicy. **Observe:** on the 46-station subset at margin 0,
   hazards/ep fell from 0.89 to 0.78, but success stayed at 0.0%. At equal hints the curve is unchanged (margin
   1.5 gave 15.2% at 9.89 hints, against 17.4% at 11.17). Kept for the fewer unsafe touches, and added
   `retrieval-ask` (margin 1.5) as a fourth named baseline rather than tuning the plain one.
5. **Reason:** prove determinism, parity, offline operation and consent in one checker. **Act:**
   check_agentgym.mjs, ag-feedback.js (ratings as DX episodes, preference pairs), the walkthrough page and the
   bundler copy. **Observe:** 30 passed, 1 failed (docs/perf/agent-baselines.json not yet written).
6. **Reason:** the after numbers on every station. **Act:** `node tools/ag_eval.mjs --seeds 3`. **Observe:**
   721 × 3 = 2,163 episodes per baseline in 187 s: expert 100.0%, retrieval-ask 11.5% (9.92 hints/ep), retrieval 0.6% (cycle 2: 0.7%; hazards/ep 0.88 → 0.79, errors/ep 23.7 → 21.7), random 0.0%. Written to docs/perf/agent-baselines.json. check_agentgym 33 passed, 0 failed.

## Seams

- `agEnv(bind, opts)` takes the same `{ room, api, SessionClass, rebuild? }` bind as `rbEnv`'s station scenarios
  (from tools/lib/headless.mjs `loadSmartCity()`). Any station room works.
- Ratings are plain DX episodes. DATAWORKS' analysis page, export, card and revoke handle them with no change.
  `agRatings()` and `agPreferencePairs()` read them back.
- COLEARN and ROBOPROG can use `agWalkthrough()` for an agent-demonstrates mode, and `docs/perf/agent-baselines.json`
  for policy-evaluation lessons.

## Left
