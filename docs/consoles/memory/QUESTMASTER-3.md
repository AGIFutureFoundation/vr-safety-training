# QUESTMASTER-3 memory — read first

Read `docs/consoles/memory/QUESTMASTER.md` and `QUESTMASTER-2.md` first; every lesson there still holds. These are the additions.

- **The stage takes the library as `lib`.** `shared/side-game-stage.js` and `shared/side-game-cosmetics.js` never spell the 3D library's usual name, not even in a comment: the bundler loads the library for any page whose module text contains it. The checker greps both files for it. World apps pass their own import (`lib: THREE`).
- **Run parity by construction.** `qmStageRun(item)` wraps `qmPlaySteps(item, qmRounds(item))`, the same list `skill-gates-ui.js`'s `play()` uses, so a world's score equals the panel's for the same choices without a second scoring rule. The checker compares the two lists as JSON and finishes an all-safe and a one-unsafe run through `qmFinishGame`.
- **A Bay World gated quest has no `practices`.** Its stage run is the three mechanic steps only (`of` = 3); the ledger marks it done on a clean run beside the quest engine's own state. That is by design: the quest is played by the engine, the mechanic by the stage.
- **The worlds start on a menu.** `bwApp.screen` and `dvApp.screen` are `"menu"` until `#menu-start` is clicked; nothing per-frame (approach toasts, the stage) runs before that, and `app.scene` is null. A browser proof clicks `#menu-start`, waits for the world to build (three seconds on the loaded machine), then places the player. Fairway needs `window.__fairwayTest.startRound()` (added this round) and then the ball placed with `app.world.placeBall`.
- **Approach hooks mount the stage.** Bay World `bwNearLockedQuest` (within fourteen of the anchor), the Deep `dvQmApproach` (a site, or a landmark that carries a K-12 course), Fairway `fwQmApproach` (the ball within twenty-five of the pin). Locked toasts, done toasts, open mounts. `qmStageMount` disposes any stage already on screen, so two never overlap.
- **The ledger key is raw when no profile is active.** `gtStorage()` returns the key unprefixed unless a profile with `ns` is selected, so a browser proof can seed `qm-side-games-v1` directly and the avatar dresses from it.
- **Stub library for the checker.** A `Proxy` whose every property is one class with `position.set`, `rotation`, `scale.set`, `add`, `remove`, `traverse`, `userData` and `dispose` is enough to build every board and count meshes. Keep new builders to those calls (plus `lib.PointLight`, guarded with `if (lib.PointLight)`).
- **Cosmetic slots are matched on words, in order.** Head before wrist before fin, shoulder last as the catch-all; test a new reward id with `qmCosmeticSlot` before you rely on where it lands. The checker wants three or more slots in use across the platform.
- **K-12 courses derive from field lessons.** `shared/k12-gates-data.js` looks each course's lesson up in `K2_FIELD_LESSONS` at import time (position, anchor, station), so the lesson must exist or the item silently drops out and the 5+ bar fails. The gate note is built from the lesson title, which must stay digit-free.
- **Adding a gated station means regenerating names.** A new `k12:` requirement fails `check_gates` with "no display name" until `node tools/gen_gate_names.mjs` runs (81 stations now).
- **Playwright on the loaded machine.** Three worlds in one script exceeded four minutes with the load average above twenty; run one world per process (`ONLY=<world>`) in the background with a log, and give `#qm-chip` a sixty-second wait.
- **Worktree guard.** A compound command that writes a file and then runs `git add`/`git commit` is refused as "too complex to verify"; one git command per Bash call passes. Python heredocs for patch scripts passed this round.
