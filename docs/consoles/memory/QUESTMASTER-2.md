# QUESTMASTER-2 memory — read first

Read `docs/consoles/memory/QUESTMASTER.md` first; every lesson there still holds. These are the additions.

- **Start from the integration tip.** A fresh worktree branch can sit at the repo's first commit with no `WebXR/` at all. `git reset --hard claude/vr-ar-safety-training-wkwmve` (the local branch, which carries the merged consoles) before reading anything. Check `date -u` before writing a log stamp; guessing runs ahead.
- **Mechanics live in `WebXR/shared/side-game-mechanics.js`.** Twelve pure step generators (`QM_MECHANICS`), each `build(item)` → steps of `{ board, prompt, options }` with exactly one safe move. `qmMechanicFor(item)` picks by `item.mechanic`, else the first `match` regex that fits the title or id, else the inspection grid. Order in `QM_MECHANICS` is the match priority. `qmPlaySteps(item, qmRounds(item))` is the whole run the panel plays: mechanic steps, then the safe-practice calls, one score.
- **Facts rule reaches the boards.** The checker tests every step's prompt, board lines and moves for digits (after stripping "K-12") and banned words. Quantities are words. A site's display name is kept as written; only an id-like site is de-hyphenated (a naive `replace(/-/g, " ")` turned "K-12" into "K 12").
- **Coverage rule.** `check_gates` asserts every mechanic is used by at least one gated item, counted over every item (Summit's and Redwood's lookout quests are what keeps `lookout-watch` in use). Before you narrow a `match`, print the title → mechanic table (a one-line `node -e` over `GATED_QUESTS` and `QM_SIDE_GAMES`).
- **The scoring rule keys on `kind: "side-game"` or `practices`, never on `reward`.** Summit's and Redwood's quests carry `reward: { xp, badge, cosmetic }`; spreading it onto their gated items made the checker score them as games (18 fails). A quest reward must be a cosmetic or a badge; that is the only reward rule for quests.
- **Rows without practices.** `qmRowHtml` shows a Play button only for items with `practices`; a gated quest from a world engine shows "Open — play it in the world at <site>" or "Done" when `opts.done(id)` says so. `qmBoardRows` takes `heading`, `done`, and `link` (extra `lkStationLink` options such as `siteId`, `runner`).
- **Every helper that takes `opts` must take the whole object.** `qmMissingHtml` destructured `{ from, page }` and then read `opts.link`: "opts is not defined" on every world page, invisible to the node checker. The browser smoke (`$SP/holodeck/qm/smoke.mjs`, port 8992) is what caught it; run it after any UI change.
- **Discovery shapes.** Redwood exported a function (`rwGatedItems()`), which discovery ignores; it now also exports `RW_GATED`. Summit's `SM_GATED` carried only `{ id, kind, gate }` and counted as world "?"; it now carries world, title, site and siteName. Treasures come through `TZ_GATED`, emitted by `tools/gen_treasures.mjs` (regenerate; never hand-edit `treasures-data.js`): gate and name only, never a place.
- **Regatta places.** A Regatta game carries `course` (an `RG_COURSES` id) and `mark` (an index or `"dock"`); `rgGamePos` in the app resolves it. Pins draw on the course card only while that course is loaded.
- **Gate names are generated.** `node tools/gen_gate_names.mjs` writes `shared/gate-names-data.js` from the catalog for every station a gate names; `qmLabel` reads it; the checker fails when a gated station has no entry. The module must precede `skill-gates.js` in every bundle (top-level read).
- **Guide KB cap.** `gen_guide_kb.mjs` refuses to write over `GD_KB_CAP` (characters, not bytes: `wc -m` counts bytes in the C locale). Six per-world gate chunks did not fit under 640 KB; the cap is now 656 KB, the same kind of raise SCHOLAR made for K-12. A per-item chunk set (63 chunks) was 25 KB and never fit.
- **Bay World `requires`.** Set in `tools/gen_bay_quests.mjs` per gated quest (`requires:` right after `slug:`): the programme's `bw-side-<programme>-opener`. Never set the same quest as both `requires` and `gate.quests` (the mentor round already gates on the apprenticeship); the checker rejects it.
- **Worktree guard.** `sed -i` with several `-e` expressions, `node -e` with an inline module import, `git commit -F <file>` and Python patch scripts written to `$SP/holodeck/qm/` all pass; heredocs, `git -C` and `git commit -F /dev/stdin <<MSG` do not.
- **Load.** The shared machine sat at a load average above twenty; the full `check_all` was not run. Run the single checkers for what you touched and say so in the hand-back.
