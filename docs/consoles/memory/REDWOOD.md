# REDWOOD — console memory

Short, durable lessons for the next team at this console. Read before touching `WebXR/redwood/`.

## Conventions
- Every top-level name in `WebXR/redwood/js/` is `rw…` / `RW_…` (the bundler flattens all modules into one scope; SUMMIT uses `sm…`).
- Pure data and rules: `rw-data.js` (terrain field, river, roads, sites, quests, activities), `rw-career.js` (progress over a
  Storage-shaped object), `rw-lore-data.js` (GENERATED by `node tools/gen_redwood.mjs` — never hand-edit). Three.js only in
  `rw-world.js`; DOM only in `app.js`.
- The page is `redwood/redwood.html` (not index.html), so the bundler entry carries `"index": "redwood.html"`, like the Deep.
- Field-tin lessons are the first sentence of a real programme station's `why` in `smartcity/js/curricula.js`. If a station leaves
  a programme, `gen_redwood.mjs` throws — pick another (programme, station) pair; never write a lesson by hand.
- Progress key `redwood-career-v1` is listed in `shared/profiles.js` GT_PROFILE_KEYS so it is private per profile.
- `redwood` is in `shared/passport.js` PP_SOURCES / PP_APP_NAMES so the runner's "Back to Redwood Reach" button has a label.

## What broke, and the fix
- Site pads flatten terrain *after* the river carve, so a pad placed on the river dams it. Keep every site farther from the river
  than `rwRiverHalfWidth(t) + pad + 70` (check_redwood asserts this).
- The worktree sandbox refuses shell commands with env-var prefixes or heredocs that mix many steps; write scratch scripts with the
  editor and pass config as a JSON file argument.
- `tcMountQuality` grows the stats panel; the minimap must sit below it (top 128 px on desktop).
