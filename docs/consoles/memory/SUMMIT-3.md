# SUMMIT-3 memory — read this after SUMMIT-2.md

Short, durable lessons for the next team at this console. SUMMIT's and SUMMIT-2's memory still hold; this adds to it.

- **Ribbon winding.** `smRibbon` in summit.js pushed its two triangles with the face normal pointing down, so with front-side Lambert materials every ribbon (pass road, service road, trails, river) was back-face culled from above. The road "showed" only as its flattened bench and the river as a fold, which is what SUMMIT-2 saw as "too faint". The order is now (l, l′, r), (r, l′, r′); check_summit holds it by text. Before blaming colour or width, hand-compute the cross product of a new geometry's first triangle.
- **Far LOD buries thin features.** At ring 2 (12 segments, 21 m vertices) a 8 m road on a slope disappears inside the mesh's chords. Frame a road still from inside ring 0–1 (the camera's chunk and its neighbours), from above: `teleport(120, 430, 0, -1.2, 380)` shows the whole switchback set.
- **Switchbacks are data, not carving.** Six vertices between the crew yard and the pass saddle; `SM_SWITCHBACKS` marks the index range. The profile is now *linear* per section (smoothstep gave zero grade at every anchor and 1.5× the average between them). Moving any road vertex shifts every along-road fraction: run `$SP/holodeck/summit-3/switchbacks.mjs`-style script (anchors in metres from `SM_ROAD_LENGTHS`, divided by `SM_ROAD_LENGTH`) and paste the printed `SM_ROAD_PROFILE` and `SM_TUNNEL_SPAN`. The terrain between legs comes out as 50–85 % faces, which the scree-fan colouring paints grey — cut faces, by design.
- **River banks must be lifted, not only cut.** The profile is a running minimum along the centre line only; ground 25 m off the line can sit below it, so the water flooded sideways. `smRawHeight` now lifts low ground within `2 × width` to the profile. A bank probe on the inside of a hairpin lands in the next segment's water: skip probes whose own distance to the polyline is under the channel width.
- **A ride is a state machine in state.js.** `smRideStart/Step/Finish` are pure and the checker drives three full rides (brake at the pull-out, late, none). In the browser the pickup moves at `speed × dt` with dt clamped to 0.05 s, so under SwiftShader (≈1 s frames) a ride crawls: for a still, set `__summitTest.ride().d = run.stop - 40` and wait, then `.d = run.to - 1`.
- **The Atlas is DOM-only.** summit-data.js is pure, so it bundles into the atlas without pulling three.js; the Summit map is hypsometric rects from `smHeightAt` on a 64-grid with runs merged (≈1,000 rects). Keep Summit ids on `data-summit-site` / `data-summit-landmark` so check_mapbox's Bay counts (`data-site=`) stay exact.
- **The combined `WebXR/dist/`** is only rebuilt by a full `python3 tools/bundle_webxr.py` (no args); `bundle_webxr.py summit` refreshes `WebXR/summit/dist/` only. Say so in the hand-back rather than spending ten minutes on the full run.
