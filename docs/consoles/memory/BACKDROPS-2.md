# BACKDROPS-2 memory — what the next GEO or BACKDROPS session needs to know

- **One budget file.** `tools/geo_budget.json` is read by `geo_bake.py` and `check_geo.mjs`; change a tier there and
  both follow. A new map is tiered by region, then by box width (`km` from `geo_maps.mjs`), then the `city` default.
- **Exclusions are flags.** `representative: true`, `procedural: true` or region `programmes` means no real backdrop:
  the bake skips it, `geoBackdropAllowed` refuses it, and check_geo fails if a picture for it appears on disk.
- **Bake timing on the shared machine:** about 30 s per single-tile city map, 90–270 s for the wide parish boxes
  (2–4 MGRS tiles). Three shards in parallel are fine; run from the worktree with `--skip-existing`.
- **The picture is in the map's scene frame**, so any change to a map's anchors (its affine fit) needs a re-bake of that
  map (`--only <id>`).
- **Relief is registry-attached, not mounted.** `relief: "3dep"` in the map data + `WebXR/assets/geo/<id>.relief.json` +
  `python3 tools/geo_relief.py maps.json --module` (rewrites `bd2-relief-data.js`). Every consumer of np-parishes.js
  sees it; a module that imports a map's data file directly does not (no grid → schematic ground).
- **After opting a map in:** drop its row in `tools/detail-baseline.json` and run `node tools/dt_measure.mjs --missing
  --engine=<commit>`; run check_parishes, check_terraform, check_detail, check_geo.
- **Bundles:** `bd2-relief-data.js` must sit right before every `np-parishes.js` in `tools/bundle_webxr.py` (the bundler
  refuses otherwise and check_geo checks it). Dist files are regenerated by the gate; restore them after a local build.
- **Headless runs** of the parishes dist need three.js routed to `WebXR/vendor/three/dist/three.module.min.js` (the page
  imports it from cdnjs, which the sandbox cannot reach).
